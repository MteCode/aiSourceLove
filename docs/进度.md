## 三、未完成

### 3.1 阻塞业务上线的（高）

- [ ] **存量客户没有联系方式**
      547 条里只有 2 条有姓名、1 条有手机号。老库 `user_name` / `contact_info` 两列本身就是空的，
      不是导入丢的。红娘现在只能靠编号 `LG000436` 找人。
      需要客户提供另一份联系方式数据（另一张表 / Excel / 红娘手上的记录），按 `serialNo` 补录。
      → 拿到文件我可以写补录脚本。

- [ ] **微信支付接入**
      现在 `PAY_PROVIDER=mock`，收不了真钱。`pay.provider.ts` 已留好抽象接口，
      需要：商户号与证书、`WX_MINI_APP_ID` / `WX_MINI_APP_SECRET`、回调域名（必须 HTTPS）。

- [ ] **短信通道接入**
      现在 `SMS_PROVIDER=mock`，验证码固定 `8888`，等于没有验证。
      `auth.service.ts:67` 已留好调用点，接阿里云或腾讯云 SDK。

- [ ] **HTTPS 与域名**
      小程序上线强制 HTTPS，微信支付回调也要求 HTTPS。
      现在是裸 IP + HTTP。需要域名 + 备案，然后 certbot 签证书（`deploy/nginx.conf` 末尾有注释）。

- [ ] **微信小程序发布**
      `manifest.json` 里的 `mp-weixin.appid` 还是空的，需要小程序账号，
      以及类目审核（婚恋交友类目要企业资质 + 可能要 ICP）。

### 3.2 功能缺口（中）

- [ ] **生日只有年份的展示问题**
      导入的档案生日统一记成 `YYYY-01-01`，后台详情页会原样显示成「1984-01-01」，
      看起来像真生日。要么加一个「精度」标记只显示年份，要么详情页对导入来源特殊处理。

- [ ] **AI 语义匹配（L3 层）没有真跑**
      `AI_PROVIDER=mock`，现在用的是 feature hashing 的伪向量——共享词越多余弦越高，
      本质是词面重合度，不理解语义。接真实 embedding 需要 API key
      （配置项已备好，DeepSeek + 通义 embedding）。
      同时要给 547 条存量档案批量生成 embedding。

- [ ] **导入档案没有归属红娘**
      547 条 `matchmakerId` 全空。需要按区域或按原运营归属分配。

- [ ] **导入档案没有关联用户账号**
      `userId` 全空，等于这些人还不能自己登录看档案。
      需要走「档案认领」流程：客户注册后用手机号匹配认领。
      → 依赖 3.1 的联系方式补录。

- [ ] **照片没有生成打码版**
      `maskedUrl` 全空。隐私分级里「没权限只能看打码版」这条现在退化成看不到图。

- [ ] **收入数据覆盖率低**
      547 条里只有 105 条有年收入。匹配引擎的收入维度对多数人退化成中性分。

### 3.3 工程债（低）

- [ ] 数据库用的是 `prisma db push`，没有迁移历史。生产应该切到 `prisma migrate`
- [ ] 没有自动化测试。状态机、隐私投影、打分函数这三块最值得补单测
- [ ] 没有 CI
- [ ] 没有日志采集与告警，出问题只能 ssh 上去 `tail`
- [ ] 备份只在同一块盘上，不防磁盘损坏。补一个云厂商的磁盘快照（服务器侧，不落本机）
- [ ] Prisma 有大版本升级提示待处理
