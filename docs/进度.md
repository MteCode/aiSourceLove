## 三、未完成

### 3.1 阻塞业务上线的（高）

- [ ] **存量照片没打码版，隐私分级被绕过**（P0，安全问题）
      `privacy.service.ts:258` 的逻辑是 `useOriginal = showOriginal || !p.maskedUrl`——
      **没有打码版时回退给原图**。导入的 460 张真人照片 `maskedUrl` 全空，
      所以对没有权限的访客也是全尺寸原图，隐私分级形同虚设。
      打码功能本身是好的（`storage.service.ts` 64px → 400px → blur(12)，不可逆），
      只是这批照片直接落盘没走上传流程。
      → 补批量生成脚本；同时考虑把回退策略改成「没有打码版就不给图」，
        当前这种「缺失即放行」的默认值在隐私场景里方向错了。

- [ ] **存量客户没有联系方式**
      547 条里只有 2 条有姓名、1 条有手机号。老库 `user_name` / `contact_info` 两列本身就是空的，
      不是导入丢的。红娘现在只能靠编号 `LG000436` 找人。
      需要客户提供另一份联系方式数据（另一张表 / Excel / 红娘手上的记录），按 `serialNo` 补录。
      → 拿到文件我可以写补录脚本。

- [ ] **微信支付接入**（需要写代码，不只是填配置）
      `WechatPayProvider` 目前每个方法都是 `notImplemented()` 直接抛错，
      真正实现的只有 `MockPayProvider`。所以这一项是**编码任务 + 资质任务**两件事：
      - 编码：用 wechatpay-node-v3 实现下单、回调验签、退款、账单查询四个方法
      - 资质：微信商户号、API v3 密钥、商户证书、回调域名（HTTPS 已就绪）
      订单状态机、权益发放、退款冲销分润这些上层逻辑都已完成且被 mock 通道跑通过，
      接真通道时不用动。

- [ ] **短信通道接入**（需要写代码，不只是填配置）
      现在 `SMS_PROVIDER=mock`，验证码固定 `8888`，等于没有验证。
      改成 aliyun/tencent 会直接抛 `短信服务未配置`——调用点留好了但 SDK 没接
      （`auth.service.ts:67`）。限流、验证码 TTL、每日次数上限都已完成。

- [ ] **微信小程序发布**
      代码侧已就绪：域名、HTTPS、小程序专用请求基址都配好了。剩下的全是账号和资质：
      1. `apps/client/src/manifest.json` 的 `mp-weixin.appid` 还是空的，要小程序账号
      2. 微信公众平台「开发管理 → 服务器域名 → request 合法域名」填 `https://flarexcode.com`
      3. 类目选「婚恋交友」，需要企业主体 + 相应资质
      4. `.env` 填 `WX_MINI_APP_ID` / `WX_MINI_APP_SECRET`（微信登录要用）

      注：本产品没有站内聊天，联系方式是解锁后线下加微信，
      所以 UGC 内容安全那一摊义务基本不适用——但这不豁免 HTTPS、域名备案和类目资质。

### 3.2 功能缺口（中）

- [ ] **生日只有年份的展示问题**
      导入的档案生日统一记成 `YYYY-01-01`，后台详情页会原样显示成「1984-01-01」，
      看起来像真生日。要么加一个「精度」标记只显示年份，要么详情页对导入来源特殊处理。

- [ ] **导入档案没有归属红娘**
      587 份档案里只有 40 份有归属红娘（全是演示数据），547 份导入档案 `matchmakerId` 全空。
      现有红娘 3 个。需要按区域或按原运营归属分配。

- [ ] **导入档案没有关联用户账号**
      `userId` 全空，等于这些人还不能自己登录看档案。
      需要走「档案认领」流程：客户注册后用手机号匹配认领。
      → 依赖 3.1 的联系方式补录。

- [ ] **收入数据覆盖率低**
      547 条里只有 105 条有年收入。匹配引擎的收入维度对多数人退化成中性分。
